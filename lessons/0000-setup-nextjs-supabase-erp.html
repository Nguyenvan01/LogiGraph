Khởi tạo Project Next.js 15, Supabase & Cấu hình Vitest

Thiết lập cấu trúc thư mục dự án VibeCoding ERP Mini, cài đặt Supabase client và tạo test mẫu kiểm tra môi trường.

⏱ ~15 phút · 🎯 Mục tiêu: Chạy lệnh npm test đạt kết quả Pass.

🌉 Tại sao cần cấu hình Test Runner trước khi viết code?

Khi sử dụng AI để lập trình, nếu không có sẵn hệ thống test tự động, bạn sẽ phải kiểm tra code thủ công bằng tay sau mỗi lần AI sinh code. Cách làm này rất chậm và dễ bỏ sót lỗi khi codebase lớn dần.

Matt Pocock đề xuất nguyên tắc: Thiết lập một automated test chạy nhanh và đáng tin cậy trước khi bắt đầu viết logic nghiệp vụ (thuật ngữ của Matt là "a loop you believe in"). Khi có sẵn test runner, AI sinh code đến đâu có thể chạy test kiểm tra ngay đến đó, kết quả đúng/sai rõ ràng.

2. Các bước cài đặt dự án

Bạn thực hiện lần lượt các bước sau trong terminal tại thư mục dự án:

Bước 1: Cài đặt các thư viện cần dùng

Cài đặt Next.js, React, Supabase JS client, Zod để validate dữ liệu và Vitest để chạy tests:

terminal (bash) 
# Cài đặt thư viện chính
npm install next@latest react@latest react-dom@latest @supabase/supabase-js zod

# Cài đặt thư viện phục vụ môi trường phát triển và test
npm install -D typescript @types/node @types/react vitest

Bước 2: Cấu hình `vitest.config.ts`

Tạo file cấu hình Vitest ở thư mục gốc để hỗ trợ alias @/* trỏ vào thư mục src/:

vitest.config.ts 
import { defineConfig } from "vitest/config";
import path from "path";

export default defineConfig({
  test: {
    // Cho phép dùng trực tiếp describe, it, expect mà không cần import thủ công
    globals: true,
    environment: "node",
  },
  resolve: {
    alias: {
      // Cấu hình alias @/ trỏ vào thư mục src/
      "@": path.resolve(__dirname, "./src"),
    },
  },
});

Bước 3: Khởi tạo Supabase client

Tạo file khởi tạo kết nối Supabase tại src/lib/supabase.ts:

src/lib/supabase.ts 
import { createClient } from "@supabase/supabase-js";

// Đọc URL và Anon Key từ biến môi trường (dùng giá trị mặc định khi chạy test cục bộ)
const supabaseUrl = process.env.NEXT_PUBLIC_SUPABASE_URL || "https://mock-project.supabase.co";
const supabaseAnonKey = process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY || "mock-anon-key";

export const supabase = createClient(supabaseUrl, supabaseAnonKey);

Bước 4: Cấu hình hệ thống file cho Agent Skills (`setup-matt-pocock-skills`)

Theo chuẩn của Matt Pocock, các skills kỹ thuật (như /to-spec, /to-tickets, /wayfinder) cần biết dự án lưu trữ issues và tài liệu ở đâu thông qua 3 file trong thư mục docs/agents/:

  • docs/agents/issue-tracker.md: Quy định nơi lưu issues (dự án này dùng local markdown trong thư mục .scratch/).
  • docs/agents/domain.md: Quy định cách đọc tài liệu nghiệp vụ (CONTEXT.md và các ADRs trong docs/adr/).
  • docs/agents/triage-labels.md: Danh sách 5 nhãn phân loại task (needs-triage, needs-info, ready-for-agent, ready-for-human, wontfix).

Bước 5: Thiết lập Hàng rào Pre-commit (`/setup-pre-commit`) & Wizard (`/wizard`)

Để ngăn chặn những đoạn code hỏng hoặc lỗi kiểu dữ liệu bị commit vào Git, chúng ta sử dụng skill /setup-pre-commit để cài đặt Husky và lint-staged:

terminal (bash) 
# Chạy wizard tương tác hướng dẫn thiết lập pre-commit
/wizard "Cài đặt husky và pre-commit hook chạy vitest và tsc trước mỗi commit"

4. Chạy Sanity Check Test

Tạo một file test đơn giản tại tests/sanity.test.ts để kiểm tra Vitest và TypeScript đã hoạt động đúng:

tests/sanity.test.ts 
import { describe, it, expect } from "vitest";
import { supabase } from "@/lib/supabase";

describe("Kiểm tra môi trường VibeCoding ERP", () => {
  it("Phép tính cơ bản hoạt động đúng", () => {
    expect(1 + 1).toBe(2);
  });

  it("Supabase client được khởi tạo hợp lệ", () => {
    expect(supabase).toBeDefined();
    expect(typeof supabase.from).toBe("function");
  });
});

Chạy lệnh test trong terminal:

terminal (bash) 
npx vitest run
