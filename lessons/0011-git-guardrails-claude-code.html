Khi cấp quyền thực thi shell cho Agent, nếu thiếu cơ chế kiểm soát biên (Guardrails), một thao tác nhầm lẫn như git reset --hard hoặc git push --force có nguy cơ làm mất các thay đổi chưa được ghi nhận trên git. Đồng thời, việc kéo dài một phiên làm việc khiến Agent bị Context Degradation, làm suy giảm khả năng chú ý và độ chính xác của suy luận. Bài học này thiết lập hai cơ chế vận hành: PreToolUse Hooks để bảo vệ mã nguồn, và Handoff Protocol để chuyển giao trạng thái làm việc có cấu trúc.

1. Git Guardrails: Kiểm soát An toàn với PreToolUse Hook

Kỹ năng /git-guardrails-claude-code xử lý bài toán an toàn khi trao quyền cho AI Agent trong môi trường dòng lệnh: ngăn chặn việc vô tình thực thi các destructive operations làm mất mã nguồn.

💡 Nguyên lý hoạt động của PreToolUse Hook

Trước khi câu lệnh được gửi xuống shell của hệ điều hành qua công cụ Bash, hệ thống kích hoạt một interceptor. Interceptor này nhận chuỗi lệnh đầu vào, đối sánh với danh mục các mẫu lệnh không an toàn. Nếu phát hiện trùng khớp, script lập tức trả về Exit code 2 kèm thông báo lỗi ra stderr, từ chối thực thi câu lệnh.

Phân loại các lệnh Git cần kiểm soát:

Lệnh Git Phạm vi ảnh hưởng Rủi ro kỹ thuật
git push (bao gồm --force) Remote Repository Nguy cơ ghi đè commit trên remote hoặc đẩy mã nguồn chưa qua kiểm duyệt lên nhánh chính.
git reset --hard Working Directory Xóa bỏ toàn bộ các thay đổi chưa commit trên working tree mà không thể hoàn tác qua git reflog thông thường.
git clean -f / git clean -fd Untracked Files Xóa bỏ vĩnh viễn các file mới tạo chưa được git theo dõi.
git checkout . / git restore . Tracked Files Hủy bỏ các chỉnh sửa cục bộ trên các file đã được git theo dõi.
git branch -D Branch Metadata Xóa nhánh cục bộ cưỡng bức mà chưa kiểm tra trạng thái tích hợp vào nhánh chính.

Cấu hình thực tế trong Dự án ERP:

Script kiểm tra được đặt tại .claude/hooks/block-dangerous-git.sh và đăng ký trong .claude/settings.json:

.claude/settings.json — Đăng ký PreToolUse Hook
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/block-dangerous-git.sh"
          }
        ]
      }
    ]
  }
}
terminal (bash) — Kiểm tra thực tế cơ chế đánh chặn
# 1. Kiểm tra với câu lệnh thuộc danh mục bị chặn
$ echo '{"tool_input":{"command":"git push origin main"}}' | ./.claude/hooks/block-dangerous-git.sh
BLOCKED: 'git push origin main' matches dangerous pattern 'git push'. Destructive git operations are restricted by project guardrails.
(Exit code: 2)

# 2. Kiểm tra với câu lệnh đọc an toàn
$ echo '{"tool_input":{"command":"git status"}}' | ./.claude/hooks/block-dangerous-git.sh
(Exit code: 0 — Cho phép thực thi)

2. Câu hỏi Trắc nghiệm Kiểm tra Nhận thức Kỹ thuật

Câu 1: PreToolUse Hook trong kỹ năng /git-guardrails-claude-code ngăn chặn câu lệnh nguy hiểm tại tầng nào?
A. Chạy sau khi lệnh git đã thực thi để tự động phát hiện và rollback commit.
B. Chặn lệnh ngay tại tầng trung gian của tool Bash trước khi chuyển xuống shell hệ điều hành, trả về Exit code 2 nếu lệnh trùng khớp mẫu nguy hiểm.
C. Tự động thu hồi quyền ghi của người dùng đối với thư mục .git.
Câu 2: Khi phát hiện lệnh nguy hiểm như git reset --hard, mã thoát (Exit code) nào bắt buộc phải trả về để công cụ Bash hủy thao tác?
A. Exit code 0
B. Exit code 1
C. Exit code 2

3. Tiêu chí Nghiệm thu Kỹ thuật (Checklist)

  • ✅ PreToolUse Hook script: Triển khai và cấp quyền thực thi cho .claude/hooks/block-dangerous-git.sh.
  • ✅ Cấu hình Settings: Đăng ký thành công hook trong .claude/settings.json với matcher Bash.
  • ✅ Kiểm thử đánh chặn: Xác nhận các lệnh git push và git reset --hard đều bị chặn và trả về Exit code 2.
  • ✅ Cho phép lệnh an toàn: Xác nhận các lệnh đọc trạng thái như git status, git diff vẫn thực thi với Exit code 0.

4. Câu hỏi tư duy (Bắc cầu sang Bài 12)

Kho lưu trữ đã được bảo vệ an toàn tuyệt đối trước các thao tác phá hoại của AI. Tuy nhiên, sau nhiều giờ làm việc liên tục, Context Window của Agent bắt đầu đầy nghẽn, dẫn đến hiện tượng Context Degradation (suy giảm độ chính xác và chú ý).
